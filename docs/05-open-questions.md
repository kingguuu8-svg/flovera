# 待解决问题

这份文档记录当前路线中还没有完全收敛、但必须持续盯住的问题。

## 1. 防止架构劣化

### 问题

AI 很容易把原型写成“能跑但不可维护”的系统：

- 逻辑重复
- 局部补丁越来越多
- 接口不稳定
- 工具链 workaround 进入核心实现
- 业务层和执行层互相耦合

### 需要解决的事

- 哪些模块必须冻结接口
- 哪些能力必须通过协议表达，而不是自由代码实现
- 哪些改动必须先过测试和回滚点
- 哪些 workaround 只能放在工具链层，不能进入核心实现

### 当前判断

- 核心执行面还算清楚
- 外围工具链和兼容层已经开始膨胀
- 如果没有明确边界，后续很容易演化成补丁堆

## 2. 借鉴成熟实现而不是照抄

### 问题

借鉴成熟沙箱设计时，容易混淆两件事：

- 借鉴设计原则
- 照抄具体实现

Android 普通 App 不能直接照抄 root、系统权限、内核控制路径。

### 需要解决的事

- 选哪些成熟案例作为主参考
- 哪些抽象可以沿用
- 哪些平台相关实现必须为 Android 重写
- 哪些能力只能作为长期预留，不能进入第一阶段

### 候选参考

- Android Virtualization Framework
- Firecracker
- gVisor
- Flatpak
- Crostini / Termina

## 结论

后续实现必须围绕这两个问题做取舍：

1. 是否会让系统变成不可维护的补丁堆
2. 是否只是照抄了不适合 Android 普通 App 的实现路径

只要答案不明确，就先停在文档和协议层，不扩大实现面。
